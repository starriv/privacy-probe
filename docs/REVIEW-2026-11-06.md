## 6. 早上验收后补修（09:38–09:50）

验收时用户反馈「白天 App 仍是暗色」，并触发了两个真实回归：

1. **主题**：App 确实由 `isSystemInDarkTheme()` 跟随系统；根因是设备 HyperOS 的 UiMode auto
   状态卡在 night（09:39 时 `mComputedNightMode=true`，而系统时间已白天）。通过
   `cmd uimode night no` → `auto` 重新计算后系统恢复浅色，App 立即变浅色；不是 App 写死深色。
   已确认 `cmd uimode night yes` 时 App 变深、`no/auto` 时变浅。截图完成后系统已恢复 auto。
2. **崩溃**：点「网络」大类时 release FC：
   `IllegalArgumentException: Key "-1" was already used`。根因是调用者列表 key 只用 `uid`，
   `uid=-1` 的未知调用者出现多行。修复：四页 Lazy 列表 key 统一加 composite/index 保证唯一；
   调用者聚合按 uid 合并（`GROUP BY uid`），Category 的调用者计数改 `COUNT(DISTINCT uid)`。
3. **Root 详情泄漏**：设置页 root 值显示 `__PR_TIMEOUT__ 1`。根因握手命令输出包含 timeout
   探测行，`substringAfter("context=")` 把后续行全带入；改为正则提取 `context=(\S+)`。
4. **截图**：设备解锁后重拍浅/深 12 张，旧「隐私雷达」截图已移除；`README` 首页恢复截图。
5. **最终构建**：release 重新构建/安装，含以上修复：
   APK SHA256 `01bbec502dc44201ca932a5e770c31f424019925573cd0ffd5badf462a8c691f`（2.2MB）；
   `testDebugUnitTest` 10/10、lint 0 errors、verify `OK=7 FAIL=0 WARN=1`。

回归验证：`assembleRelease`、`testDebugUnitTest`、lint 均需在最终提交前再跑一次（见下）。
